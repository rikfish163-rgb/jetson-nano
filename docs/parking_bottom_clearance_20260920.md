# 前进入库：按车头与库底线的距离停车

用户确认：车头前沿停在库底线前，不压线。采用已有配置 `parking_bottom_clearance_m: 0.04` 作为目标余量。

## 本次停车原因

日志 `b926559f-30d6-4541-8708-7820ee088b7d/Pasted text.txt` 中，时间戳 `1789905147.230558` 已缓存 PARKING，`1789905152.19956` 由蓝线触发，随后完成蓝线对齐、前进和等待，进入 PARKING。

`1789905162.638444` 的最终状态是 FINISHED / `parking_bottom_detected`。当时关联库底线在后轴坐标系中的端点为 `(1.39356, 0.24427)` 和 `(1.42865, -0.08878)`，仍在约 1.4 米前方。按当前车身尺寸估算，最近车头角到线还有约 1.077 米，到 4 厘米目标停车位置还差约 1.037 米。

错误在 `ForwardParking.command()`：只要 `bottom` 非空就直接完成，没有判断车是否到达。并非未识别到 P，也不是此次雷达停车。

## 修复行为

- 看到与 P / 车库两侧匹配的底线后，继续前进入库。保留底线位置，同时继续提取可见的两侧白线并居中。
- 复用 `WhiteParking.remaining()`：由当前位姿将底线转到车体坐标系，计入轴距 0.26 米、前悬 0.07 米及车宽 0.24 米。斜线按靠近底线的车头角计算沿车身方向的余量。
- 距目标停车位置剩余不超过 `parking_final_max_m`（0.30 米）时，用已有最终入库速度 8；远处使用入库速度 12。
- 到达预留 4 厘米的位置才进入 FINISHED，原因统一为 `parking_at_bottom_clearance`。
- 底线进入近处摄像头盲区后，保留已经测得的世界坐标，通过当前位姿更新剩余距离。仍要求摄像头观测持续刷新；图像过期不会被报告为入库完成。
- 日志增加 `remaining_m`、`bumper_clearance_m`、`target_clearance_m`、`bottom_age_s` 和 `distance_source`，便于区分新测量与底线位置加位姿估算。

当前位姿模式是指令积分估算，不是实测里程计。因此 4 厘米是控制目标；相机标定、车身尺寸、实际速度与停车惯性仍影响实车最终位置。未启动实车验证。

启动参数无需改变；重新启动主控后加载更新后的 Python 文件。
