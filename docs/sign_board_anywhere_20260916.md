# 全画面路牌候选修复（2026-09-16）

权重仍为 Nano 的 `robodata/models/20260915_10000/resnet18_candidate.onnx`，

本次没有重训、启动摄像头/ROS/执行器或修改行驶状态机。
工作区是 Nano 工作区的挂载，代码已经写入 Nano；识别节点下次启动加载。

## 实现

- 删除候选中心必须位于画面上方 72% 的限制，搜索全画面。
- 删除轮廓面积必须达到全图 0.2% 的门槛；最低要求为宽高至少 12 像素、
  轮廓面积至少 72 像素。没有最大面积限制，边缘裁剪限定在图像范围内。
- 保留颜色、宽高比、蓝色牌内部浅色字符检查，避免将地面蓝线直接当牌。
- 对最大边不超过 32 像素的小蓝色候选，增加轮廓占包围框至少 55% 的检查。
  该条件用于拒绝细小锥桶残片，不套用到较大或被遮挡的牌面。
- 仍将面积最大的有效候选送给分类模型；没有增加逐帧多次 CPU 分类。
  面积不是距离测量，未实现多目标追踪或路口归属判断。
- `/debug/sign_board_frame` 显示候选框、拒绝原因和分类结果。
  信息栏放在原图上方，不再覆盖原图顶部 82 行；输出画面高度增加 104 像素。
- 识别消息/截图 JSON 增加候选诊断、裁剪时间、分类时间和源图像年龄。
- 除原有成功识别截图外，拒绝结果最多每 2 秒保存一次，每次进程最多 60 组；
  保存原图及实际裁剪（如果存在），没有候选时不制造假裁剪。
  同一目录中的 `NO_CANDIDATE` / `REJECTED` 文件用于追查漏检。
  `capture_dir` 为空时仍不保存，包括现有只读 preview 配置。

大牌回归，最终仅对小候选加形状检查后重新跑完整 3000 张并获得上述结果。

九个位置并缩放到四种贴片长边，合成 504 个回归场景：

| 合成贴片长边 | 正确接受 | 低分拒绝 | 错误接受 |

候选提取：旧算法找到 288/504，新算法找到 504/504。
这只是位置和尺寸回归，不包含真实远距离成像、运动模糊、眩光或遮挡。
